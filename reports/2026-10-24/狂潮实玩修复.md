# 火力狂潮实玩修复

2026-10-24。重做场景漏接了巨人预警和血条，攻击也沿用了锁定玩家位置的主线逻辑，导致巨人身体在一侧、另一侧小队却无预警损兵。本轮修复战斗判定与反馈，并通过浏览器触屏事件从开局打到结算、检查重试和模式切换；没有只依赖模拟器或快速推进。

## 确认并修复的问题

| 问题 | 修复与复核 |
|---|---|
| 巨人远离队伍仍锁定队伍位置砸击，重做场景没有显示预警和血量 | 狂潮近战以巨人自身位置为横向中心，前方范围有界；恢复同一判定区域的红色预警、血条、击中/闪避反馈。触屏看到预警后换道，无 Boss 损兵；站在范围内仍会受伤。其他模式攻击规则保持原样。 |
| 激活距离以外的开局红军停住 | 初始狂潮敌人直接激活，远处队列持续前进。定向回归检查 40 米外单位实际移动。 |
| 约 82 游戏秒后蓝色 +1 门耗尽 | 补足蓝门、弹药牌和炮架队列；完整 UI 试玩到最终战仍有前方补给，并测试到 120 游戏秒。 |
| +1/+99 与损兵、击破反馈不足，密集命中耗尽共享特效预算 | 补给和砸击提供实际结果飘字；命中、敌人死亡、士兵死亡采用独立预算，避免命中特效吞掉死亡反馈。 |
| 小屏/大军团队尾被底部操作面板覆盖 | 镜头依据实际队尾留出操作区域；320×568、390×844 和 844×390 的 240 人布局场景均复核。 |
| 横屏沿用远景镜头，整条桥缩成一条窄线 | 横屏改为桥头近景，优先保证当前交战和队伍可见。 |
| 结算标题折行遮挡内容，指引把左右增兵方向说反 | 标题保持单行；明确左侧 +1 增兵、黄色 +99 装弹和红色危险带。 |
| 狂潮仍显示不生效的主线升级/战术、+0 金币结算 | 狂潮菜单说明固定军备，隐藏无关购买入口和奖励区；军械库禁购，皮肤操作提示固定蓝军。隔离的有余额存档测试确认不误扣款，切回防线后正常升级。 |
| 常驻“补给已放行”误导，部分长开场横幅裁字 | 狂潮只显示实际危险提示；长开场文字按屏幕宽度排版。 |
| 结束时残留火箭、切换场景可能残留飘字 | 胜败时清空飞行火箭，退出狂潮时回收其 DOM 飘字和短时特效。 |

## 实际操作记录

第一局逐段用鼠标拖动和按键复现：左侧增兵、右侧拆炮、中央装弹、使用超载、暂停/继续，正常客户端节奏打到约 93 游戏秒。复现了 18 人的无预警 Boss 损失、末段蓝门消失和错误结算。

修复后用 CDP 的真实触屏输入逐段操作，并中途暂停检查：完整通过四只巨人，结算剩 122 人，接 79 扇增兵门、44 张装弹牌，拆 66 个炮架；Boss 损兵为 0。主线资源、升级和进度保持一致；再来一局和暂停重试均回到 36 人、120 发初始弹药。之后撤退、回主页、切换防线并再次开战。

新增 `scripts/carnage-playthrough.ts` 固化这些 UI 路径。只读取 `__game` 作断言，操控通过触摸事件、按钮和键盘完成；不写兵力、不直接调用世界更新、不使用 `speed` 或 `autoplay`。在最终镜头改动后再跑一整局通过：约 92.83 游戏秒，150 人，107 次增兵、31 张装弹牌，14 次实际点击超载，Boss 损兵为 0，页面异常 0。

独立的 240 人镜头压力测试和有余额购买测试明确作为 fixture 记录，未混入完整试玩数据。它们不代表通过实际增兵达到 240 人。
